<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/auth/otp/send | Untrusted phone input crosses into OTP generation |
| backend → Eskiz.uz HTTP API | Backend credentials + message content cross to an external SMS provider |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan | ASVS |
|-----------|----------|-----------|-------------|-----------------|------|
| T-01-01 | DoS / Spoofing | OTP send (SMS cost abuse, SMS-bomb) | mitigate | Per-phone Redis rate limit (INFRA-01, Plan 03) + existing per-IP `@Throttle(5/hr)` on `otp/send`; Eskiz client no-ops without creds in dev | V2 |
| T-01-02 | Info Disclosure | Eskiz credentials (ESKIZ_EMAIL/PASSWORD) | mitigate | Read from ConfigService/Vault; never log credentials; only log `{phone, status}` not the message body in prod | V6 |
| T-01-03 | Spoofing | Eskiz bearer token | mitigate | Cache token in-memory only (instance field); re-auth on 401; never persist token to disk/DB | V2 |
| T-01-04 | Injection | message content sent to Eskiz | mitigate | OTP message is server-composed (no user-controlled free text in the SMS body); phone validated by DTO | V5 |
| T-01-SC | Tampering | npm installs | accept | No new npm packages in this plan — Eskiz is a direct HTTP client (RESEARCH: do NOT add `eskiz-sms` wrapper) | — |
</threat_model>
