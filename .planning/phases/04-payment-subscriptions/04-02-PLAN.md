<objective>
Wave 1 — close the financial perimeter. Land all four critical webhook + atomicity + timeout deliverables:

1. **PAY-01 — Payme JSON-RPC webhook hardening**: typed DTOs replacing `any`; `IpWhitelistGuard` + `@IpWhitelist("PAYME_IP_WHITELIST")` on the controller route (permissive default per Phase 3); RedisLockService SETNX with 24h TTL keyed by `webhook:payme:{params.id}:{method}` wrapping the dispatcher; storeResponse on first hit; replay returns cached response identically.
2. **PAY-02 — Click webhook hardening**: typed DTOs + IpWhitelistGuard + RedisLockService idempotency keyed by `webhook:click:{click_trans_id}:{action}`. Signature formula is ALREADY corrected in Plan 04-01 Task 1 — this plan adds the 5-minute sign_time skew window check (R2 anti-replay) and the service_id env validation guard.
3. **PAY-03 — Atomic transactions**: rewrite `_performTransaction` and `_cancelTransaction` (Payme) and `complete()` (Click) so Payment + Invoice + Subscription updates run inside a single interactive `prisma.$transaction(async (tx) => ...)`. Pass `tx` into the dispatch handler. Write `AiAuditLog` inside the same transaction (§VIII.4 append-only requirement).
4. **PAY-04 — 12h timeout**: register `PaymentTimeoutProcessor` (queue was registered in Plan 04-01). `_createTransaction` enqueues with deterministic `jobId: payment-timeout:{payment.id}` and 12h delay. `_performTransaction` and `_cancelTransaction` remove the job (idempotent — missing-job catch swallowed). Processor double-checks `status === "PENDING"` before flip-to-FAILED to handle the race where Payme confirms at hour 11:59. CancelTransaction reason=4 is returned when our timeout was the trigger (Payme docs verified 2026-06-07).

Purpose: This plan is the security/correctness backbone of Phase 4. Without it, Click rejects every real callback (signature bug — fixed Plan 04-01) AND duplicate Payme retransmissions double-process (PAY-01) AND a crash mid-handler leaves the system in inconsistent state (PAY-03) AND stuck PENDING payments block invoices forever (PAY-04).

Output: 2 new DTO files; 1 new processor; refactor of payme.service.ts + click.service.ts + payment.controller.ts + payment.module.ts; extension of existing 567 + 303 LOC specs. No schema changes (Subscription.frozenReason migration lives in Plan 04-03 alongside the state machine validator).
</objective>
