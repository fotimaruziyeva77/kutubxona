<objective>
RPT-01 + RPT-02 monthly PDF reports. Three deliverables:

1. **`ReportDataService.gatherForScope` + parameterized `PdfService.buildMonthlyReportHtml` (RPT-01)** — new service that gathers scope-specific stats: for `scope='national'` reuses existing `getNationalStats`; for `scope='viloyat'` aggregates viloyat-level stats + top-5 active libraries + top-5 active readers (with `maskNameIfMinor` defense-in-depth from Phase 3); for `scope='tuman'` similar but tuman-scoped. Returns the unified `{ title, period, tableRows, charts? }` shape consumed by `buildMonthlyReportHtml`. Per D-6, the template is parameterized via `(data, scope, scopeId)` — no new templating engine. `escapeHtml` applied to every DB-sourced string at template render (Plan 05-04 carry-over).

2. **`ReportEmailProcessor` (RPT-02 reports queue consumer)** — `@Processor(REPORT_QUEUE)` consuming the 215 jobs enqueued by the monthly cron. Each job: `ReportDataService.gatherForScope(scope, scopeId, periodStart, periodEnd)` → `PdfService.generateFromHtml(buildMonthlyReportHtml(data))` → `notificationQueue.add('email', { email, subject, html, attachments: [{ filename, content }] })`. Concurrency capped at 2 per PITFALLS M6 (215 simultaneous Puppeteer renders OOM the server).

3. **`generateMonthlyReports` cron + parameterized download endpoint (RPT-01/02)** — `@Cron('0 5 1 * *', { name: 'monthly-reports', timeZone: 'Asia/Tashkent' })` fires on the 1st of each month at 5am Tashkent. Reads all viloyats + tumans from replica, resolves recipient userIds per scope, enqueues 215 jobs with deterministic jobId per (scope, scopeId, YYYY-MM). The existing `GET /admin/reports/monthly` endpoint is parameterized to accept `?scope=viloyat&scopeId=UZ-08` (and stays scope-asserted for tier admins via Plan 05-02 helpers).

Purpose: RPT-01 (scope-parameterized PDF) + RPT-02 (auto-monthly + emailed) close. Reuses Plan 05-04 NOTIFICATION_QUEUE email path so attachments flow through MailClient with escapeHtml. Plan 05-09 (landing B2B) consumes a similar email pattern for demo requests.

Output: 1 new service (ReportDataService) + 1 new processor (ReportEmailProcessor) + 1 new cron (generateMonthlyReports) + parameterization of existing controller + PdfService template extension + new ADMIN_NOTIFICATION_EMAILS fallback usage. ~14 new tests. REPORT_QUEUE already registered (Phase 1).
</objective>
