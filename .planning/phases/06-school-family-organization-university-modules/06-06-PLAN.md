<objective>
Kitob o'qish soati (ORG-03) — HR admin creates events, employees scan QR to
mark attendance, HR uploads photo/video evidence, PQ-9 report consumes monthly
counts. This plan reuses every primitive from Plans 06-01 (MinIO, scope util,
ReadingHourMedia model) and 06-04 (file-type sniff, sharp thumbnail, DRAFT→
PUBLISHED state machine). The new piece is the rotating-HMAC QR pattern that
prevents screenshot abuse (per CLAUDE.md §VIII.1 dynamic QR + §XV.R22).

Purpose: PQ-9 §9b mandates kitob o'qish soati every month for every idora.
Without QR attendance + photo evidence + monthly counts surfaced in the PQ-9
PDF, the platform's compliance proof is empty. This plan delivers all three
flows.

Output: ~7 source files, ~30 new specs, 3 frontend pages.
</objective>

| Boundary | Description |
|----------|-------------|
| employee browser → QR scan landing | Authenticated employee; HMAC token in URL is the proof-of-presence |
| QR generation cron → DB | NONE (QR is computed on-demand per-request; no scheduled write) |
| reading-hour media upload | Multipart with MIME sniff + size cap (mirrors Plan 06-04) |
| Public QR scan page | Auth required to attend — token alone is not enough |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-R1 | Spoofing | QR screenshot replay (employee not at event) | mitigate | HMAC token rotates every 5 minutes; CLAUDE.md §VIII.1 + §XV.R22 require dynamic QR; constant-time HMAC compare via crypto.timingSafeEqual; tolerates one prior window |
