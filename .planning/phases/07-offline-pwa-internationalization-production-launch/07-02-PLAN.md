    1. Create apps/frontend/lib/offline/sync.ts — Background Sync replay logic:
       - Export async function syncPendingTransactions(): Promise of { synced: number, failed: number }.
       - Read all entries from offlineDb.syncQueue ordered by createdAt ascending.
       - If queue is empty, return { synced: 0, failed: 0 }.
       - FIRST call fetch("/api/auth/refresh", { method: "POST", credentials: "include" }) to get a fresh access token from the HttpOnly refresh cookie. Parse the response JSON for accessToken. This handles PWA-05 (expired 15-min JWT during 12h offline).
       - For each queued entry, call fetch(entry.url, { method: entry.method, body: entry.body, headers: { "Content-Type": "application/json", "Authorization": "Bearer " + freshAccessToken } }).
       - On 200/201: delete entry from syncQueue, increment synced counter.
       - On 409 (Conflict): call resolveConflict(entry, response) from conflict-resolver. If resolution returns "retry", update the entry body with server version and retry. If "discard", delete from queue.
       - On 401: the refresh token itself expired. Stop sync, keep remaining entries in queue.
       - On other errors: increment retryCount on entry, set lastError, keep in queue.
       - Export async function queueOfflineTransaction(method, url, body, accessToken): void — creates a new SyncQueueEntry with uuid v4 id, stores in offlineDb.syncQueue, and requests Background Sync registration via navigator.serviceWorker.ready.then(reg => reg.sync.register("sync-transactions")).
       - Export async function getPendingSyncCount(): Promise of number — returns offlineDb.syncQueue.count().
       - Export async function clearSyncQueue(): void — clears all entries (used on logout).

    2. Create apps/frontend/lib/offline/conflict-resolver.ts — PWA-06:
       - Export type ConflictAction = "retry" | "discard".
       - Export async function resolveConflict(entry: SyncQueueEntry, response: Response): Promise of { action: ConflictAction, updatedBody?: string }.
       - Parse response body for serverVersion or updatedAt field.
       - Strategy: last-write-wins — if server has newer updatedAt, discard the client change. If client is newer or equal, retry with the server's version field merged into the body.
       - For transaction-type URLs (/api/transactions, /api/bookings), always discard on conflict (server state wins for book inventory).
       - For other URLs, merge server version into body and retry.
