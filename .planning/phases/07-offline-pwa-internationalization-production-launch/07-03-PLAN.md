       - Add a new export MULTI_SCRIPT_SETTINGS object with analysis config:

         filter "cyrillic_to_latin" with type "icu_transform", id "Cyrillic-Latin".
       - Update BOOKS_INDEX_MAPPING.settings to merge MULTI_SCRIPT_SETTINGS into the existing UZBEK_ANALYZER_SETTINGS. The merged settings should have both the uzbek_standard/uzbek_search analyzers AND the new multi_script analyzer.
       - Update BOOKS_INDEX_MAPPING.mappings.properties.title to add a "cyrillic" sub-field: { type: "text", analyzer: "multi_script" }. This allows Cyrillic queries to match Latin-indexed titles.
       - Update BOOKS_INDEX_MAPPING.mappings.properties.author similarly — add "cyrillic" sub-field.

    2. Update apps/backend/src/infra/elasticsearch/elasticsearch.service.ts:
       - In the ensureIndices method (or equivalent index creation/update logic), when creating the books index, use the merged settings that include both UZBEK_ANALYZER_SETTINGS and MULTI_SCRIPT_SETTINGS.
       - In the search method for books, update the multi_match query to include the .cyrillic sub-fields alongside the existing fields. E.g., fields: ["title", "title.cyrillic", "author", "author.cyrillic", "title.keyword"].
       - This ensures a query in Cyrillic (e.g., "Алпомиш") matches the Latin-indexed "Alpomish" via ICU transliteration.

    3. Create apps/backend/src/infra/elasticsearch/__tests__/multi-script.spec.ts:
       - Test: MULTI_SCRIPT_SETTINGS has analyzer.multi_script with icu_tokenizer.
       - Test: MULTI_SCRIPT_SETTINGS has filter.cyrillic_to_latin with type "icu_transform" and id "Cyrillic-Latin".
       - Test: BOOKS_INDEX_MAPPING.mappings.properties.title.fields.cyrillic exists with analyzer "multi_script".
       - Test: BOOKS_INDEX_MAPPING.mappings.properties.author.fields.cyrillic exists with analyzer "multi_script".
       - These are unit tests on the configuration objects — they do NOT require a running ES instance.
